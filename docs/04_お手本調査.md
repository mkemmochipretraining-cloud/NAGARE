# 各段の書式のお手本（2026-11-14 調査）

← [README](../README.md)

ソフトや半導体の外の分野も含め、各段の書式に取り込める型を調べた。
ほぼすべてのお手本に共通する部品は、**「この段に入ってよい条件」と「この段を出てよい条件」を前もって書いておくこと**。

| 段 | お手本 | 取り込む部品 |
|---|---|---|
| ① 意図 | 指揮官の意図（目的・重要な任務・最終状態、リスクを受け入れる所）／Amazon PR/FAQ／トヨタ A3 | 最終状態、受け入れるリスク、想定問答、今の状態（数字） |
| ② 仕様 | ISO/IEC/IEEE 29148（必要・単一・解釈1通り・検証可能）／決定の記録 ADR | 要求ごとの ID、あいまい語の禁止一覧、判断の記録 |
| 2.5 検証項目 | 建設の検査試験計画 ITP（合格基準・停止点・立会点・責任者）／ISO/IEC/IEEE 29119-3 試験文書（開始・終了の基準、独立性） | 要求ID と検証項目の対応、合格基準、検査点の種類、独立性の宣言 |
| ③ 計画 | WBS の100％ルール（漏れなし・範囲外なし・重なりなし）／WBS 辞書 | 作業包ごとの「含む・含まない・合格基準」、分解の合計が要求の100％か |
| ④ 実装 | 医療の引き継ぎ SBAR（状況・背景・評価・提案）／WHO 手術安全チェックリスト（3つの区切り） | 始め・途中・終わりの点検、終わったときの SBAR 形式の報告 |
| ⑤ 検証 | ITP の停止点（解除されるまで先へ進めない）／トヨタ A3 の原因分析 | 合否の表、不合格の原因の分類、戻し先 |
| ⑥ 記録・考察 | 米陸軍の AAR（何が起きるはずだったか／実際に何が起きたか／なぜ／次に何を続け・変えるか）／Google SRE の責めない事後検証 | AAR の4つの問い、弊害の記録、無駄の許容線 |
| ⑦ ローンチ | Google のローンチ点検表（量の見積もり・負荷試験・冗長性・監視・段階的な公開・バックアップ・外部依存）／NASA の審査（入口・審査・出口の基準） | 出す・出さないの判定表、戻し方 |

## 検討時の注意
- お手本の多くは人から人への受け渡しのための型。AIからAIへ使うと合わない点が出る可能性がある（例：SBAR の「評価」をAIが書くと、根拠のない見立てが混ざるおそれ）
