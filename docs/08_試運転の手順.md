# 試運転の手順（一度回す）

← [README](../README.md)

## ねらい
- flow を小さな実際の仕事で一度通し、書式・エージェント・hook が実際に回るかを確かめる
- 物差しの「今の値」（論点 d）を取る。保留にした崩れる条件（D4 の理由、D23 など）を、実際の記録から書けるようにする
- 回して困ったところから、残りの論点（e 差分の見せ方、g 副本を作る段）を決める

## 0. 準備（一度だけ）
1. Claude Code の版を確かめる：`claude --version` が **v2.1.116 以上**（エージェント定義の hooks が `--agent` で働く版）
2. hook は `python3` で呼ぶ。Windows で `python3` が使えない場合は、定義ファイルの `command:` の `python3` を `py -3` などに直す
3. 題材のプロジェクトに入れる

```bash
python3 scripts/install.py <題材のプロジェクト> --design rtl,tb   # 設計物のフォルダに合わせる
```

4. ⑦まで進める場合は、署名の鍵を用意する（[07_エージェント定義.md](07_エージェント定義.md) の「承認の仕方」）

## 1. 回し方
段ごとに、新しい会話を `claude --agent` で起動する。承認はあなたが書式ファイルの `status: approved` と `approved_by` を直接書く。

| 段 | 起動 | あなたがすること |
|---|---|---|
| ① 意図 | `claude --agent nagare-intent` | 依頼文を渡し、質問（1回最大3問）に答える。意図メモを承認する |
| ② 仕様 | `claude --agent nagare-spec` | 判断の記録の選択肢を選ぶ。仕様を承認する |
| ③ 計画 | `claude --agent nagare-plan` | 失敗とアラートの条件を確かめる。計画を承認する |
| 2.5 検証項目 | `claude --agent nagare-vplan` | 検査点（停止・立会・書類）を決める。検証項目表を承認する |
| ④ 実装 | `claude --agent nagare-impl` | 止まった項目に答える |
| 2.5 テスト | `claude --agent nagare-vplan` | （つながりの作業包のあと、ポート一覧ができてから）テストのコードを書かせる |
| ⑤ 検証 | `claude --agent nagare-verify` | 特採・修理・廃棄、停止点の解除を決める |
| ⑥ 記録・考察 | `claude --agent nagare-review` | 振り返りを考察し、承認する |
| ⑦ ローンチ | `claude --agent nagare-launch` | 試運転では省いてよい |

## 2. 記録すること（物差し・論点 d）
| 指標 | 取り方 |
|---|---|
| 段ごとの token | 各会話の終わりに `/cost` などで使った量を見て、⑥の「物差しの記録」に写す |
| 出戻りの回数と戻り先 | ⑤の不合格の分類と戻し先、⑥への仕様変更の申し出から数える |
| 人が判断に使った時間 | 承認・回答に使ったおおよその分数をメモする |
| hook に止められた回数 | 止められた操作と理由を、⑥の「弊害の記録」に入れる |

## 3. 回したあと
- ⑥の振り返り（scope: full）で、flow そのものの改善案を出し、NAGARE の別ブランチに変更案として出す（D20）
- 決めること：論点 d の「今の値」と目標、e・g、保留にした崩れる条件
