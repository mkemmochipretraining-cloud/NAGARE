## 起動の仕方（あなたと途中でやりとりするため）
各段は、**その段のエージェントになりきった会話**として起動する。

```bash
cd <プロジェクト>
claude --agent nagare-intent     # ①意図。②以降も同じく nagare-spec などに置き換える
```

- `--agent` で起動すると、会話の本体がそのエージェントの指示文・使える道具・モデルで動く。本体なので AskUserQuestion であなたに質問でき、答えを受けて続けられる
- 段ごとに新しい会話を起動するので、前の段の会話の記憶は持ち込まれない（独立が保たれる）
- エージェント定義の hooks 欄は、`--agent` で起動したときにも働く（Claude Code の v2.1.116 から）。使う前に `claude --version` で版を確かめる
- AskUserQuestion は tools に明示しないと使えないので、8つの定義すべてに入れてある
- 夜に人がいない作業（主に④）は、質問ができない形で動かしてもよい。その場合、人に聞くことが出たら止まって理由を残す（P14）

## 許可の出し方（D8）
エージェントが設計物を読もうとして止められると、範囲と理由を報告して終わる。人が `nagare/permits.json` に次を書くと、その範囲だけ読めるようになる。

```json
[
  {"agent": "nagare-vplan", "path": "rtl/top.sv", "until": "2026-11-21T00:00:00+09:00",
   "reason": "ポート一覧にない信号の確認", "granted_by": "masa"}
]
```
期限切れ、または `granted_by` が空の許可は無視される。

## 分かっている限界（flow を回して確かめる）
1. **Bash からの読み書きは止められない**：Bash を持つ ③④⑤⑥ は、シェルのコマンドで hook を通らずにファイルを扱える。この4つはもともと設計物を読めるので、読む側の害は小さいが、④が Bash でテストのコードに触ることは防げない。許可制の ①②2.5⑦ には Bash を渡していない
2. **サブエージェントとして呼ぶと、途中で人と直接やりとりできない**（AskUserQuestion がサブエージェントでは使えないため）。そのため各段は `claude --agent` で会話の本体として起動する（上の「起動の仕方」）。サブエージェントとして呼ばれた場合は、質問を返して終わる
3. **承認の印（status: approved）の書き換えは止めていない**：ファイルの中の一部の欄だけを守ることは、この hook ではできない（未決の論点 f）
4. **エージェント定義の hooks 欄の動き**：サブエージェントの定義に hooks を書く形は Claude Code の資料に沿っているが、使う版で実機確認が要る
