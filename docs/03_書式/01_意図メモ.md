# ①意図メモの書式（確定・D9）

← [README](../../README.md)

## 役目
AIが聞き手になって、推測では埋められない欄（目的・物差し・制約・やらないこと など）を人から聞き取り、②仕様に渡す。
空いた欄はAIがもっともらしい推測で埋めて先に進んでしまい、そのずれは⑤まで見つからないため、ここで埋め切る。

## お手本
- 軍の「指揮官の意図」：目的・重要な任務・最終状態、リスクを受け入れる所
- Amazon の PR/FAQ：作る前に、未来の報道発表と想定問答を書く
- トヨタの A3：背景・現状（データで）・目標（数字と期限）

## 聞き手のAIの動き方
1. 依頼文を読み、欄ごとに「埋まっている／あいまい／空」を判定する
2. 「あいまい」と「空」の欄だけを、**1回に最大3問**、できるだけ選択肢を付けて聞く
3. 答えに数字のない「多い・少ない」などがあれば、その場で聞き返す
4. 空欄がなくなったら草案を出し、出口の条件を機械で確かめる
5. 人が承認したら②へ渡す（approved に変えるのは人だけ）

## 書式

```markdown
---
id: INT-001
stage: 1-intent
version: 1
status: draft            # draft / approved（approved に変えるのは人だけ）
prev: none
written_by: ai
approved_by:             # 人の名前と日付。空なら未承認
---

## 1. 目的
（「〇〇のため」の形で1〜2文。誰が何に困っているか）

## 2. 最終状態
（終わったときに、何がどうなっているか）

## 3. 今の状態
- 書き方：数字 ／ 段階（どちらかを選ぶ）
- 内容：（例：手戻り 3回/週、または 段階 1／3：試作は動くが例外処理なし）

## 4. 物差し
| 指標 | 今の値 | 目標 | 測り方 |
|---|---|---|---|
|  |  |  |  |
（今の値と目標は、数字か段階の番号で書く）

## 5. 制約
- 期限：YYYY-MM-DD
- 使う道具・環境：
- 守る規約：
- 触ってはいけない所：

## 6. やらないこと
| やらないこと | どのプロジェクト段階までやらないか | 理由 |
|---|---|---|
|  |  |  |

## 7. 受け入れるリスク
（どこなら失敗や遅れを許すか）

## 8. 想定問答
| # | 問い（使う人／内部） | 答え |
|---|---|---|
| 1 |  |  |
| 2 |  |  |
| 3 |  |  |

## 9. AIが聞いたことと答え
| 回 | AIの質問（1回に最大3問） | 人の答え |
|---|---|---|

## 10. 決まっていないこと
- （なければ「なし」）

## 11. 出口の条件（機械で判定）
- [ ] 1〜8 と 10 に空欄がない
- [ ] 3 と 4 の今の値・目標が、数字か段階の番号になっている
- [ ] 5 の期限が日付になっている
- [ ] 6 に1行以上ある
- [ ] 8 に3問以上ある
- [ ] 10 が「なし」、または承認者が先送りを認めている
- [ ] status が approved で、approved_by が埋まっている

## 12. 申し送り（②仕様へ）
- 決まったこと：
- 次の段がやること：

## 13. 変更の記録
| 日付 | 何を変えたか | 誰が |
|---|---|---|
```

見出し部分を1つと数えて、欄は全部で14個。①は副本（.yaml）を作らない案（機械の判定に要るのは先頭の YAML だけで、それは .md の中にあるため）。
