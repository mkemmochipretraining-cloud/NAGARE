# ⑦ローンチ判定の書式（確定・D21）

← [README](../../README.md)

## 役目
作ったものを外に出すかどうかを、人が決める。
ローンチの種類（FPGA の書き込みデータの配布／IP の提供／テープアウト／社内向けの配布 など）は、**製品や事業の段階ごとに、その都度決める**。

## 土台：半導体設計のローンチ（テープアウト・リリース）の作法
| 作法 | ⑦での形 |
|---|---|
| サインオフがすべてそろう | ⑤の判定がすべて「合格」か「例外つき合格」か、特採として承認済み |
| 凍結と版の付与 | ③で決めた凍結の時点を確かめ、出すものに版（タグ）を付ける |
| リリースの中身をそろえる | 出すものの一覧を作る |
| 正誤表 | ⑥から申し送られた特採を、正誤表にする |
| 締め切りのある出口 | 出す日と締め切り（製造の受付など）を書く |

## 採用した他業界の知見
| # | 知見 | 出どころの業界 | 書式での形 |
|---|---|---|---|
| P25 | 担当ごとに「出してよいか」を表明させる | 宇宙（NASA の飛行準備審査） | 「3. 各段の判定」。①〜⑥の各エージェントが、出してよい／条件付き／だめ と理由を1行で出す |
| P26 | 中止の条件と、戻れない点を先に決める | 航空 | 「4. 中止の条件と戻れない点」 |
| P27 | 段階的に出し、戻し方を用意する | ソフト（段階的な公開） | 「5. 段階と戻し方」。チップは戻せないので、主に FPGA や IP の配布で使う |
| P29 | 引き渡しの書類をそろえる | 建設 | 「6. 引き渡しの書類」 |

P28（作った人とは別の人が出荷を判断する）は、今は一人で回すので保留。後で考える。

## ローンチのAIの動き方
1. ローンチの種類を、人に確かめる（製品・事業の段階で決まる）
2. ①〜⑥の各エージェントに、自分の段から見た判定と理由を出させる
3. 出すものの一覧・版・正誤表・引き渡しの書類をそろえる
4. 中止の条件と戻れない点、段階と戻し方の案を書く
5. 人に判断を求める（出す／条件付きで出す／出さない）
