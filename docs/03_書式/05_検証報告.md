# ⑤検証報告の書式（確定・D17・D18）

← [README](../../README.md)

## 役目
2.5 が書いたテストを、④の設計物に対して機械が流し、合否を出す。不合格が出たら、検証エージェントが原因を見立てて戻し先を決める。

## 土台：半導体設計の検証の作法
| 作法 | ⑤での形 |
|---|---|
| 回帰試験 | 作業包ごとに、関係するテストを全部流す。ランダムな入力の種（シード）を記録する |
| サインオフの判定 | EDA コンソールの6つの状態（合格・不合格・例外つき合格・空振り・基準なし・判定前）で書く |
| 網羅率を閉じる | 2.5 の「網羅の目標」に届いたかを見る。届かなければテストを足すか、理由を書く |
| 例外は理由付き | 例外は理由と承認者を記録する（eda.yaml の waiver） |
| 停止点 | 2.5 で決めた停止点（P1）は、人が解除するまで先へ進めない |

## 採用した他業界の知見
| # | 知見 | 出どころの業界 | 書式での形 |
|---|---|---|---|
| P16 | 不適合の処置の区分 | 建設・製造の品質管理（不適合報告書） | 「4. 処置」。特採は人の承認が要る |
| P17 | 条件付きで先へ進める（最低装備リスト） | 航空 | 「5. 条件付きで進めるもの」 |
| P18 | 鑑別診断 | 医療 | 「3. 不合格の一覧と鑑別」。原因の候補を2つ以上、根拠付きで並べてから見立てる |
| P19 | 管理図で不安定さを見る | 製造（統計的な工程管理） | 「7. 傾向」 |

## 不合格の原因の分類（D18）
| 名前 | 中身 | 戻し先 |
|---|---|---|
| Design level fail | 設計物が、仕様や検証項目のとおりになっていない（数値は正しいのにタイミングを満たしていない場合を含む） | ④ 作り直し |
| Verification level fail | 検証項目やテストのコードが、仕様から見て正しくない（テストのコードの誤りを含む） | 2.5 手直し |
| Specification level fail | 仕様そのものが実運用に堪えない | ⑥経由で ② |
| EDA level fail | SDF など設計環境の数値や、ツールの設定が原因 | 道具側（EDA リポジトリ） |
| Andon fail | 鑑別診断で原因を絞れなかった | 緊急度を上げて人が見直す。繰り返す中で分類の判断基準を育てる |

**空振りの扱い（B と C の組み合わせ）**
- サインオフ判定で空振りが出たら、その時点で**不合格と同じに止める**（C）
- 空振りは「症状」として扱い、なぜ空振りになったかを鑑別診断で見立て、**上の分類のどれかに振り分ける**（B）。例：テストの前提の誤り → Verification level fail、ファイルの場所の指定の誤り → EDA level fail

## 処置の区分（P16）
| 区分 | このflowでの意味 | 承認 |
|---|---|---|
| 手直し | 戻し先で直し、同じテストを流し直す | 不要 |
| 修理 | 完全には直さず、決めた条件の範囲で使える状態にする | 人 |
| 特採 | 直さずに、そのまま受け入れる | 人（必須） |
| 廃棄 | 作業包ごと作り直す（③に戻して分け直す） | 人 |

## 検証エージェントの動き方
1. ④の実装報告（引き渡し前の点検がすべて pass）と 2.5 のテストがそろったかを確かめる（入口）
2. EDA のフローでテストを流し、検証項目ごとにサインオフを判定する
3. 空振り・不合格は止めて、原因の候補を2つ以上、根拠（ログ・波形の場所）付きで並べる
4. 見立てから分類を決め、戻し先と処置の区分を決める。絞れなければ Andon fail
5. 特採・修理・廃棄・条件付きで進めるもの・停止点の解除は、人に聞く（1回に最大3問）
6. 合格率と、時々だけ落ちるテストの割合を記録する
7. 報告を⑥へ渡す

## 9. 出口の条件（機械で判定）

- [ ] すべての不合格に、分類・戻し先・処置の区分がある
- [ ] 修理・特採・廃棄には、承認者が書かれている
- [ ] 条件付きで進めるものには、期限と承認者が書かれている
- [ ] 停止点の VI は、人が解除している

- [ ] Andon fail には、見直しの相手と期限がある
