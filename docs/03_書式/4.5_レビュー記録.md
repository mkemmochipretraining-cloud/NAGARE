# 4.5 レビュー記録の書式（案・D29）

← [README](../../README.md)

## 役目
④実装が終わった作業包を、Claude とは別のモデル（Codex、D27）がレビューした結果を残す。指摘ごとに、人が「採る・採らない・仕様に戻す」を決める。

- 書くのは hook（`nagare_codex_review.py`）。IMPL の `status` が `done` になったときに1回だけ動く（D29）
- 判定（`verdict`）は Codex が出す。**振り分けは人だけが書く**
- レビューの判定は、テストの合格の代わりにしない。合否は⑤で決める

## 判定（verdict）
| 判定 | 意味 | 次の段 |
|---|---|---|
| PASS | 直すべき指摘がない | ⑤へ |
| PASS_WITH_WARNINGS | 軽い指摘だけ | 人が振り分けたあと⑤へ |
| NEEDS_REVISION | 直すべき指摘がある | 人が振り分けたあと④へ戻す（仕様の抜けなら②へ） |
| BLOCKED | レビューできなかった（Codex が動かない、時間切れ、出力が読めない） | 人が原因を見る（Andon） |

## 指摘の重さ
| 重さ | 意味 |
|---|---|
| P0 | 動かない・壊れる（仕様の要求に反する、合成できない） |
| P1 | 高い確率で不具合になる（リセット漏れ、クロックをまたぐ所の扱い、ラッチ） |
| P2 | 規約の違反で、Lint が拾わないもの |
| P3 | 読みやすさ |

## 物差し（D29）
- 採る指摘が10件中2件に満たなければ、レビューを置くかどうかを考え直す。`nagare_status.py` が、すべてのレビュー記録を数えて表示する

## 書式

```markdown
---
id: CRV-IMPL-01
stage: 4.5-review
version: 1
status: pass_with_warnings   # pass / pass_with_warnings / needs_revision / blocked（hook が書く）
prev: IMPL-01
written_by: codex
reviewer: codex exec（読むだけの砂場）
reviewed_at: 2026-12-01T10:00:00+09:00
git_commit: 1a2b3c4
---

## 1. 指摘
| ID | 重さ | 場所 | ルール ID | 指摘 | 根拠 | 振り分け（人） | 理由（人） |
|---|---|---|---|---|---|---|---|
| F1 | P1 | rtl/tk_lib_sfifo.sv:42 | — | DEPTH=1 のときポインタの幅が0ビットになる | `$clog2(1)=0` | 仕様に戻す | DEPTH≥2 を仕様に足す |
| F2 | P3 | rtl/tk_lib_sfifo.sv:18 | R-NAME-08 | 信号名の接尾辞が規約と違う | 規約 R-NAME-08 | 採らない | 例外。理由は行に記載済み |

振り分けは「採る」「採らない」「仕様に戻す」のどれか。空欄のあいだは次の段に進めない。

## 2. Codex の要約
（Codex の最後の返事の要約。AI が作成）

## 3. 出口の条件
- [ ] すべての指摘の「振り分け（人）」が埋まっている
- [ ] status が pass か pass_with_warnings なら⑤へ、needs_revision なら④か②へ、blocked なら人が原因を見る
```
